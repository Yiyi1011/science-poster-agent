# 分镜自动修正工作台（手动微调可选）

## 从哪里打开

点击首页“自动修正太阳案例分镜”，或打开 http://127.0.0.1:5173/?view=storyboard 。

当前工作台针对已制作的太阳案例7镜。主流程是系统自动处理，不要求使用者自己逐镜修改。普通打开页面不触发写入或付费调用。

## 日常使用：只点一次主按钮

1. 点击“自动检查并修正”。系统实际检查7镜，自动拆长字幕、补足阅读/录音时长，复检后自动保存草稿与运行记录。
2. 默认查看简短摘要：修正N项、涉及M镜、格式阻断项前后数量，以及真实完成的四个步骤。无需“应用修正”或另点“保存”。
3. 想了解细节时展开“查看修改前后”，按镜头显示原内容、新内容、修改原因。红绿底色辅助，另有明确文字标签。
4. 点击左侧镜头查看当前草稿；实际被本轮修改的字幕/时长标记“系统已修正”。右侧原视频仍是已认可的67秒版本，不冒充更新后的成片。
5. 没有可安全修改的问题时，只保存检查记录，不硬改内容或制造新版本。无法安全处理、内容待审核与格式已修好是不同状态。

当前自动能力是本地确定性规则，不是Qwen视觉审核。旁白含义、画面科学性自动改写及重配音/新视频生成尚未接入此页，不宣称整个视频闭环已经完成。

## 可选：亲自微调

中间“手动微调（可选）”默认折叠。需要时展开，可编辑标题、旁白、字幕、时长、画面说明，填写修改说明后单独保存。

- 手动保存和系统修正分开标记；手动改完后旧运行卡会注明“历史运行记录”，不沿用自动高亮。
- 自动运行前若有未保存输入，本次会保留它们，并把“输入改动”和系统实际修正分别留档。
- 旁白改变才标记该镜待重配；字幕/时长调整可复用原录音，但依然需要重渲染。清单始终相对已生成基线计算，避免连续编辑漏掉待办。
- 来源编号、科学边界锁定。文字含义改变保留复核提示，不能沿用旧版认可。
- 载入历史内容后保存成新版本，不删除旧版；冲突时先导出当前草稿，再加载最新合并。

## 当前自动处理范围

| 检测情况 | 自动动作 | 边界 |
|---|---|---|
| 字幕超过18字 | 优先按标点无损拆分，保留全部字符 | 不擅自概括或改变事实 |
| 每条字幕不足2.5秒 | 延长镜头并对齐24fps | 不加速旁白 |
| 时长短于可复用录音 | 根据实测录音加停顿延长 | 不截掉录音结尾 |
| 拆分后超过6条或无法无损拆分 | 保留原文、记录未解决原因 | 不悄悄删除内容，不宣称修好 |
| 旁白/画面含义与基线不同 | 标注待科学复核/待重新配音 | 不自动认定专家审核通过 |

系统一次请求即完成本地检查、修正、复检和保存。界面只在请求期间显示进行中，成功后显示真实步骤记录，不用假计时模拟长流程。

## 向评委展示可复现的过程

1. 展开“检查记录与测试入口（可选）”，点“载入长字幕练习”。这是明确标记的人工测试输入，未保存、不改原片。
2. 点击主按钮“自动检查并修正”。系统应自动拆分第3镜字幕，并从9.375秒延长到10秒：2项修正，无需手动编辑、应用或保存。
3. 查看摘要和前后对照；字幕拼接后的原文完全相同，只改分卡和阅读时长。输入之前被替换的字幕单独算输入改动，不计作自动修正。
4. 刷新页面，检查记录和差异仍然存在。再次检查同一草稿可得到无需进一步自动修改的记录；历史选择框可以查看前一次修正。
5. 练习创建的草稿不替换原片；如需恢复，可载入v0并通过可选手动保存恢复为新版本。

不能把练习输入说成模型实际犯错，也不能把草稿变化说成新MP4已经生成。评委材料需清楚区分“本地规则修正”“模型审核”“人工复核”和“已重新生成”。

## 留痕与故障保护

- `POST /api/videos/editor/solar/auto-run` 由服务器计算修正，不接受客户端伪造修改列表。
- 使用SQLite同一事务保存草稿版本和运行记录：写入失败两者一起回滚。
- 每轮带UUID运行编号；网络丢失响应后再次点击复用同编号，同请求不会重复保存，不同输入不能盗用同编号。
- 版本检查避免多窗口互相覆盖。自动保存也遵守此约束，冲突不执行修正。
- `automatic_runs`保存输入快照/哈希、方法、时间、四阶段记录、原值/新值/原因、运行前输入改动、复检状态、版本关联、媒体未更新标志。
- “检查记录”显示最近10次，完整记录仍在数据库；“导出当前草稿JSON”含最近10次记录及当前草稿，不含密钥。
- 默认数据库 `artifacts/storyboard-editor/solar-drafts.sqlite3` 已被Git忽略；只读基线不创建数据库，第一次主动运行即会创建。
- 配置 `SCIENCE_POSTER_DATA_DIR` 后写入该目录。云端若是临时目录，不保证持久存储；部署前需接持久存储。
