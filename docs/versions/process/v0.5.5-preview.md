# 制作过程 v0.5.5-preview

本版解决“检索不到足够资料就永远无法出片”的最后一个堵点，并清理无效的重检索入口。

## 本版修复

- 已有分镜可直接制片（用户决策）：当最新版本已有分镜但未完全通过证据自动检查（review_status=blocked/pending）时，界面新增“已有分镜，直接用现有稿制作视频”按钮。点击需确认，后端 `reserve_media` 在收到 `proceed_from_blocked` 标志后才放行（默认仍拒绝），并在媒体记录写入 `proceeded_from_blocked` 留痕；播放区显示“本片由你确认后直接使用未完全通过证据检查的稿子制作，发布前请再人工核对内容”。自动制片流程（execute_with_video）门禁不变，仍严格。
- 根因：真实案例“不同地方水的颜色为什么会不一样”（bcb58391）——研究第 2 次找到 1 份来源（河南英文网湖泊变蓝变绿文章，仅讲变化趋势），生成稿反复补充光学机制细节（红光吸收/蓝光散射/藻类/具体年数）超出该来源范围，证据检查连轮 blocker，版本在 blocked/pending 间循环，共 9 个版本而分镜完好。新按钮让负责人可对已有分镜直接出片。
- 移除无效按钮：降级提示块的“复制问题，使用新版重新检索”对同一问题重跑结果必然相同（检索词与后备目录不变），删除之；保留“未找到可核对的公开网页，本片基于AI初步解释生成，内容未经外部来源核实”如实标注。想换问题重搜仍可走“复制为新项目”。

## 验证

- 后端完整测试：188 项全部通过（新增 1 项：blocked 版本默认拒绝制片、显式确认后放行且留痕、已过检版本不留痕）。
- 前端生产构建通过（`tsc -b` + `npm run build`）；新包实测含“直接用现有稿制作视频”按钮、无“复制问题，使用新版重新检索”文案。
- 后端重启后实测：`proceed_from_blocked` 字段被新模型接受（404=项目不存在而非 422 校验错误）。

## 边界

- 这是制作过程候选，不创建 `final/` 标签。公众试听、领域人员科学终审、正式名称/团队/盖章报名表和提交PDF逐页检查仍未完成。
- 直接制片跳过的是“自动证据检查”这一关；人工判断未跳过——媒体记录与界面均保留用户确认标记。
- 政治敏感话题仍不进入自动制片；明显危险或无法核实的断言会降级为说明而非默许。
- 公开部署、云资源创建与最终提交包仍需负责人另行确认。
