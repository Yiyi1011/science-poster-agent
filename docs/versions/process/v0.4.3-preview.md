# 制作过程 v0.4.3-preview

## 本版目的

用户确认右侧自动制片与成片直显已经达到目的，同时指出字幕仍会按固定字数把一句话截断，下一条只剩“信。”等残句。用户准备由Claude＋DeepSeek继续开发，因此本版既修字幕可读性，也建立不含密钥的代码、私有数据和提示词交接点。

## 字幕修复

- 字幕由“每22字一个cue”改为按`。！？!?`等完整句子切分；短的无标点尾部自动并回上一句。
- 长句仍是一个时间cue，只在画面和SRT内部按像素自动换成两行或三行，不改变旁白文字。
- 字幕背景高度随行数调整；时间仍按该完整句占本镜旁白字符比例分配，并沿用实际PCM时长和非负递增硬校验。
- 复用原6镜画面和6段旁白零模型调用生成`preview-20260901T053314449721Z.mp4`，旧片和两次程序修正记录均保留。
- 第4秒为完整陈述、第8秒为完整问句、第40秒为同一cue内的两行完整句，确认不再出现固定字数残句。

## 交接与回退

- 新增`docs/CLAUDE_DEEPSEEK_HANDOFF.md`，列出必须提供的材料、Claude主开发提示词、DeepSeek独立审查提示词、官方Qwen模型限制、预算和回退方法。
- 新增`backup_private_runtime.py`：使用SQLite在线备份API取得一致快照，连同媒体和证据压缩到本地私有目录；明确排除`.env`并做数据库完整性检查和SHA256清单。
- Claude和DeepSeek只用于编程/审查，不能替换参赛应用运行时的阿里云百炼Qwen模型。两者不得同时修改同一工作树；建议Claude实现、DeepSeek审查已提交diff。

## 验证与边界

148项后端测试和前端生产构建通过。新测试覆盖完整句拆分及短尾合并；真实重合成新增付费调用0。自动分句依赖标点，极端无标点长旁白会保持为一个cue并在画面内多行显示，因此后续仍要完整试听。当前仍是制作过程版，没有发布`final/v1.0.0`，也没有完成公网部署或专家/公众终审。
